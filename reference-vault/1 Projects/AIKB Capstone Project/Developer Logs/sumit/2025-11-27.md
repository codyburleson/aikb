# Devlog 2025-11-27, Sumit

## Updates

Pushed some big updates today. Mainly focused on fixing some annoying bugs and making the agent a bit smarter about where it puts things.

## What's New

### New Tools & Capabilities
- **`query_metadata(key, value)`**: It's like SQL for the vault. I can find notes by tag, type, or any other frontmatter field.
- **`search_notes(query)`**: Added a proper text search. Now the agent can find stuff based on content, not just tags.
- **`delete_note(filename, folder)`**: Finally added a delete function. Useful for cleaning up when the agent makes a mess (or when I do).
- **Dynamic Templates (`load_templates`)**: The agent now loads templates dynamically from the folder. I don't have to hardcode them anymore; I just drop a `.md` file in `Templates/` and the agent knows how to use it.

### Tweaks & Fixes
- **Path Safety**: Fixed `_get_safe_path` so it stops complaining about "File not found" when I give it an absolute path that's actually inside the vault.
- **Update Fix**: `update_content` and `update_frontmatter` were failing on relative paths (like "Folder/Note.md"). Fixed that by forcing a path resolve check first.
- **JSON Crash**: The agent was crashing whenever it saw a date in the YAML frontmatter (`TypeError: Object of type date is not JSON serializable`). I added a `_sanitize_metadata` helper to convert dates to strings before JSON encoding.
- **Templates**: Pointed `load_templates` to the right folder (`reference-vault/3 Resources/Templates`). It was looking in the wrong place before.
- **Default Template**: Added a `default.md` template. Now if I ask for a generic note, it doesn't just fail or make something up; it uses this basic template.

### Agent Logic
- **Context**: The agent now scans the vault at startup and lists the *actual* folders it sees. This stops it from hallucinating folders that don't exist.
- **Safety**: Added a rule: if the agent wants to create a note in a folder that doesn't exist, it has to ask me first. No more creating random folders.
- **Display**: Told the agent to stop showing me the raw metadata unless I ask for it. Keeps the chat cleaner.
- **Fixed Entry Point**: Restored the `if __name__ == "__main__":` block so the script actually runs.

### Standard Instruction
- ANALYZE INTENT: Determine the type of note (Person, Project, etc.)
- DISPLAY PROTOCOL: Updated System Instructions to enforce a "Content-Only" display protocol
- FOLDER SAFETY PROTOCOL: match preferred folder structure
- SEARCH STRATEGY:  First, try 'query_metadata' (e.g., key="type", value="Person").
                    Second, use 'search_notes' for text content
- VERIFICATION RULE (STOP & ASK): Before calling 'create_markdown', check if your target 'folder' exists. If it doesn't, ask for permission first.

## Bugs I Squashed

### 1. The "Path Blindness" Bug
**Issue**: The Agent could read a note but couldn't update it. Kept saying "File not found".
**Why**: The agent uses relative paths ("3 Resources/..."), but the python script was checking existence against the current working directory.
**Fix**: Always resolve the path to the absolute vault path *before* checking if it exists.

### 2. The "Phantom Content" Bug
**Issue**: Created notes were empty. Metadata was there, but no content.
**Why**: The template file was broken. I used double quotes in the terminal when creating it, so bash ate the `{content}` variable.
**Fix**: Rewrote the templates using a python script to ensure the placeholders are actually preserved.

### 3. The "Date Crash"
**Issue**: Agent crashed on any note with a date.
**Why**: `python-frontmatter` gives us `datetime` objects, but `json` hates them.
**Fix**: Added a sanitizer middleware to convert all dates to strings before serializing.

### 4. The "Shallow Scan"
**Issue**: Agent kept trying to create "Person" folder even though "3 Resources/Persons" existed.
**Why**: `os.listdir` only looks at the top level. It didn't know about the subfolders.
**Fix**: Switched to `os.walk` to get a full map of the vault. Now it knows what's actually there.

### Code Refactoring & Cleanup (Maintenance)

#### A. Standardization of Imports
Change: Moved asyncio, os, and load_dotenv from the middle of the script to the global header. Rationale: Adhering to Python PEP 8 standards. Having imports scattered throughout the file makes dependencies hard to track. Centralizing them ensures the execution environment is clear immediately upon opening the file.

#### B. Removal of Gemini Class Import
Change: Deleted from google.adk.models.google_llm import Gemini. Rationale: We switched to String-Based Configuration.

Before: Manually instantiating a model object (model = Gemini(...)).

After: Passing the model name directly to the agent (model='gemini-2.5-flash').

Benefit: The ADK handles the instantiation internally, reducing boilerplate code and making it easier to switch models just by changing a string.

#### C. Deprecation of load_memory Tool
Change: Removed from google.adk.tools import load_memory and removed it from the Agent's tool list. Rationale: Specialization of the Agent.

The Runner and InMemorySessionService already handle the immediate conversation context (Short-term memory) automatically.

We wanted to force the Agent to rely on the Vault (read_markdown, query_metadata) for information retrieval rather than checking its internal chat logs. This reduces tool confusion and ensures the Agent acts as a "File System Manager" rather than a generic chatbot.

#### D. Centralized Tool Management
Change: Consolidated all local tools (create_markdown, read_markdown, etc.) into src.tools.markdown_ops. Rationale: Separation of Concerns. The agent.py file is now purely for Orchestration (configuration and logic), while markdown_ops.py handles Execution (disk I/O). This makes the codebase modular and easier to test.
